# 初回状態移行手順

この手順は homert02/03 を routerd2 の新規 BIOS ディスクへ一台ずつ移すときの境界を定める。
旧 routerd の状態ディレクトリを丸ごとコピーしない。旧デーモンと新しい PID 1 が同じカーネル
資源、DHCP 配布、Tailscale 識別情報を同時に所有しないことを前提にする。

## 入力と所有者

|入力|取得元|新しい配置|停止が必要な境界|扱い|
|---|---|---|---|---|
|Tailscale の保存済み識別情報|旧機の`/var/lib/tailscale/tailscaled.state`|`/var/lib/routerd/services/tailscale/tailscaled.state`|旧`tailscaled`停止、プロセス・`tailscale0`・ルーティングテーブル52 の消失確認後|内容を解釈しない通常ファイルとして一度だけ複写する|
|SSH ホスト鍵|旧機の選択済み Ed25519 ホスト鍵|`/var/lib/routerd/ssh_host_ed25519_key`|管理接続の切替時|既存の管理ホスト識別情報を保持する必要がある場合だけ複写する|
|DHCPv4 リース|停止済み旧 dnsmasq リースファイル|新ディスクのネイティブ DHCP サービス状態|旧 DHCP サーバー停止後|`routerd dhcp import-leases` で取り込む|
|DHCP 固定割当履歴|停止済み旧 routerd SQLite DB と`-wal`/`-shm`|新ディスクのネイティブ DHCP サービス状態|旧 DHCP サーバー停止後|リース取込成功後に`routerd dhcp import-sticky`で取り込む|
|router YAML|現行の運用者設定|新しいイメージの`/etc/routerd/config.json`|停止不要|変換・検証済み設定をイメージ作成にだけ渡す|

旧 routerd のリース・状態・データベース、Tailscale の状態ディレクトリ全体、鍵のない EnvironmentFile、
実行時ソケット、カーネル状態は入力にしない。内容を解釈しない状態の内容、鍵、SHA-256 値は記録・出力・
Git にコミットしない。

## 一台の実行

1. 新しいディスク、ネイティブ設定、回復用コンソールと旧機を再起動できる管理経路を準備する。新ディスクは
   新規出力にだけ作る。既存ディスクを上書きするビルダーは使わない。
2. 旧機をまだ動かしたまま、設定だけを`routerd config migrate`と`routerd config validate`に通す。
   Tailscale の状態、リース、固定割当履歴 DB をこの段階で読んだりコピーしたりしない。
3. 承認された停止時だけ、旧 DHCP/Tailscale を止め、旧プロセス、`tailscale0`、Tailscale ルーティングテーブル52、
   UDP 41641 の旧所有者と DHCP 待受が消えたことを確認する。消えない場合は新ディスクを起動しない。
4. root 専用の空の作業ディレクトリを作り、表の選択済み通常ファイルだけをコピーする。ディレクトリは0700、
   ファイルは0600とし、複写前後の SHA-256 をその場で比較するが値を端末出力・文書・履歴へ残さない。シンボリック
   リンクとデバイスファイルは受け入れない。
5. `DISK_STATE_DIR` にその作業ディレクトリだけを渡して新ディスクを作る。ビルダーは新規 ext4 状態パーティション
   にだけ複写し、`services/tailscale` を Tailscale エンジンの状態ディレクトリとしてマウントする。リースと
   固定割当履歴は新ディスクの停止状態で、リース取込を先、固定割当履歴取込を後に実行する。
6. 起動直前に作業ディレクトリのモードとファイル種別、複写の SHA-256 一致、ネイティブ設定の検証、ディスクマニフェストの
   `initial_state_provisioned`、旧所有者不在を確認する。新しい PID 1 を一台だけ起動し、独立した対向機から
   Tailscale ノード識別情報、IPv4/IPv6 TCP/UDP、DHCP 更新、新規 DHCP クライアント、DNS、WAN/LAN 通信を確認する。
7. 失敗したら新 PID 1 を止めてから旧サービスを起動する。旧状態の再 SHA-256 が停止時の値と一致することを
   その場で確認し、専用ディスクと作業ディレクトリを削除する。二つの所有者を同時に起動して復旧しない。

各ノードは同じ手順を独立に実施する。二台切替、既存 TCP/UDP 継続、実回線負荷は、この初回起動合格の後の別受入である。

## 空の状態ディスクの確認

2026-11-01 に `main` の`3e2a73a`で通常の `make image` 出力から、空の0700作業ディレクトリを指定して
`build-disk-image.py` で新規 `/dev/vda2` 状態パーティションを作成した。読み取り専用マウントでは`lost+found`以外の
項目はなく、同じ root 専用ディスクを隔離マウント名前空間の QEMU で起動して Linux PID 1 の
`ROUTERD_READY`を37.7秒で確認した。これは状態ボリュームの空開始と起動経路の確認であり、旧状態の
複写、Tailscale 識別情報、リース/固定割当履歴の取込、対象機への切替は確認していない。ディスクと作業ディレクトリは確認後に削除する。
